### 개발하던 애플리케이션의 목적

- 학생과 직장인들을 위한 알림 등록 플랫폼
- 아이디, 비밀번호 없는 discord OAuth 단일 로그인
- 지하철 정기, 도착 임박 discord DM 알림 제공
- 점심 메뉴 추천 discord DM 알림 제공(현재 건대입구역 쪽으로 한정)

### 현재 상황

- 현재 상황
    - 월별로 나가는 고정 비용이 부담스럽다
    - 3-tier 웹 애플리케이션 구조
    - 별도의 scale-out 구조 없음

### 현재 시스템 아키텍처

![](/assets/img/알람봇-v2-1/image.png)

- 백엔드는 단일 EC2 내 2개 컨테이너에서 모두 처리한다.
    - API 서버 컨테이너: 로그인 인증/인가 처리, 사용자 요청에 따라 알림을 RDS에 등록
    - Bot 컨테이너: RDS에서 폴링하여 알림 발송
- CloudWatch 연계 관련해서는 미구현 상태다.

### 현재 인프라 비용 계산

1. 고정 비용
    - EC2
        - t3.micro 시간당 USD 0.0144 * 730 = 10.512 USD
        - EBS: 20 * GB당 USD 0.0912 * 730 = 1.82 USD
    - ALB:
        - 고정 비용: 시간당 USD 0.0225 * 730 = 16.43 USD
        - 최소 2개 AZ에 public IP가 붙은 노드:  USD 0.0005 * 730 * 2 = 7.30 USD
    - RDS
        - db.t4g.micro(2 vCPU 1 GiB 메모리): 시간당 0.025 USD * 730 = 18.2500 USD
        - EBS 볼륨: (GB당 월별 0.131 USD) * (20 GB) = 2.62 USD
    - ElastiCache Serverless
        - 저장 데이터 1GB 당 1시간 0.101 USD
            - Redis OSS, Memcached 라면 1GB 단위로 과금, 100KB 저장해도 1GB로 올려침
            - Valkey 라면 100MB 단위로 과금, 100MB 이하 데이터일 경우 시간당 0.0101 USD
            - 0.0101 USD * 730 = 1달 7.373 USD
    - 합산: 64.305 USD = 92581.83 원
    → 트래픽이 전혀 없어도 1달에 십만 원 가까이 지출되며, 꽤 부담스러운 금액..
2. 트래픽에 따른 변동 비용
    - ALB에서 퍼블릭 인터넷으로 나갈 때 egress 비용
        - GB당 USD 0.09
        - ALB → EC2는 cross AZ임에도 예외적으로 무료
    - ALB: Σ(시간당 4개 차원 중 가장 큰 LCU) * 0.008 USD
        - 아래 내용 1줄 요약: ALB는 트래픽이 커질수록 온디맨드 구조가 된다.
    - ElastiCache Serverless
        - 백만 ECPU당 0.0027 USD
            - "ECPU": 대략적인 요청 횟수를 나타내는 지표인데 다음과 같이 계산한다.
            - `ECPU += max(1, 전송한 KB수, (요청 처리 CPU 시간) / (GET/SET CPU 시간))`

> **시간당 LCU 계산 공식** — 1 LCU는 이 정도의 용량 제공을 뜻한다.
>
> | 차원 | 1LCU당 용량 |
> | --- | --- |
> | 새 연결 수 | 초당 25개 |
> | 활성 연결 수 | 분당 3,000개 |
> | 처리된 바이트 | 시간당 1GB |
> | 규칙 평가 | 초당 1,000개, 단 요청당 10개까진 무료 |
>
> 1시간당 LCU를 계산하며, 아래 네 값 중 가장 큰 값을 취한다.
>
> ```
> max(
>     새 연결수 기준으로 몇 LCU?,
>     활성 연결 수 기준으로 몇 LCU?,
>     처리된 바이트 기준으로 몇 LCU?,
>     규칙 평가 기준으로 몇 LCU?
> )
> ```

### 목표

부담스럽지 않은 비용으로 계속 배포해 놓는, 번듯한 구성을 갖춘 1인 웹 서비스

- **AWS에서 트래픽이 없을 때는 비용을 최대한 줄이고, 트래픽이 늘어나면, 자동으로 scale-out 하는 인프라를 구현한다.**
- CloudWatch Logs, Alarms를 활용한 로그 처리로 Observability 확보, scale-out 구현을 통해 기본적인 1인 애플리케이션 운영 구조를 마련한다.
